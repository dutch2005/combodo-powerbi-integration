# Locale-Neutral Power BI Template Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release the Power BI helpdesk template as 1.1.0 with locale-neutral CSV ingestion that preserves the existing report model and refreshes for every iTop-supported LTR account language.

**Architecture:** Fork the official template repository, extract the existing `.pbit` into source-controlled PbixProj/TMDL, replace the four localized `Web.Page` query pipelines with shared M functions over `format=csv&no_localize=1`, and compile with a digest-pinned pbi-tools Core image. Static contract fixtures cover English, German, Dutch, and French; artifact round-trip and Power BI Desktop refresh provide end-to-end evidence.

**Tech Stack:** Power Query M, Power BI PbixProj/TMDL, pbi-tools Core 1.2.0 container, PowerShell contract tests, GitHub Actions.

**Spec:** `H:/Github/combodo-powerbi-integration/docs/superpowers/specs/2026-09-04-locale-neutral-powerbi-broad-php-design.md`

## Global Constraints

- Preserve every existing page, visual, measure, relationship, parameter, and output table column.
- Never depend on translated display labels or translated enumeration captions.
- Keep the report UI English; support all iTop-supported LTR account languages without per-language maps.
- Explicitly test English, German, Dutch, and French fixtures.
- Keep the original 1.0.x `.pbit` available for rollback; do not delete generated assets.
- Keep every `.m`, `.ps1`, and other code file at or below 200 physical lines.
- Never commit credentials, reachable private URLs, or unsanitized production responses.
- Assign the issue and PR to `dutch2005`; apply labels and the `1.1.0` milestone; use a closing reference to the issue number captured in Task 1.
- Do not claim live refresh unless Power BI Desktop actually completes a refresh against a reachable test iTop instance.

### Task 4: Implement shared locale-neutral Power Query functions

**Files:**
- Modify: the extracted model/Mashup expression sources under `src/CombodoPowerBI/`
- Create or expose expressions: `BuildExportUrl`, `FetchQueryCsv`, `RequireColumns`, `ShapeUserRequest`

- [ ] **Step 1: Implement `BuildExportUrl`**

The function accepts a Query Phrasebook URL, parses existing query parameters, replaces any existing `format` value with `csv`, adds `no_localize=1`, and rebuilds the URL without duplicate keys. It rejects null/blank required URLs and never logs the authorization header.

- [ ] **Step 2: Implement `FetchQueryCsv`**

The function accepts query name, URL, login, and password. It rejects blank credentials, builds `Basic <base64(login:password)>`, calls `Web.Contents`, and parses UTF-8 CSV with explicit delimiter and quote behavior. Before promotion/shaping, detect HTML/login/error payloads from response metadata and leading content; raise a concise `Error.Record` naming the query and remediation, never the credentials.

- [ ] **Step 3: Implement `RequireColumns`**

The function compares `Table.ColumnNames` with an exact required internal-code list. When fields are missing, raise `Error.Record` containing the query name and comma-separated missing codes plus guidance to verify the Query Phrasebook URL and credentials.

- [ ] **Step 4: Implement `ShapeUserRequest`**

Use the legacy table's exact canonical names and types. Select by internal codes, rename only after validation, and split date/time strings inside M so the previous date and time columns remain available. Keep this function shared by `UserRequest` and `UserRequest_Period`.

- [ ] **Step 5: Keep functions modular**

If the Mashup representation allows separate expressions, keep each function separate. If it requires one section file, keep the section below 200 physical lines by moving schema lists and shapers into separate shared expressions.
